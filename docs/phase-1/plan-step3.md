# Phase 1 — Step 3: API Skeleton, Database, Local Dev, CI/CD, and New Hosting

## Goal

1. Create `apps/api` (Fastify + Drizzle) and `apps/jobs` (Azure Functions) skeletons.
2. Establish the database migration process and the first tables (`site_settings`, `audit_log`).
3. Provide one-command local development (Postgres/PostGIS, Azurite, Mailpit).
4. Create CI + deploy workflows for web, API, and jobs.
5. Bring the public site back online: front end on Static Web Apps at `https://<DOMAIN>`,
   API at `https://api.<DOMAIN>`.

No new user-facing features yet. Locally, the map behaves as before. In deployed environments,
member cards and legislation will fail until step 4 (the Congress.gov key is intentionally not
passed to CI builds) — that is acceptable.

## Prerequisites

- Step 2 complete: dev and prod resources exist; names recorded in `values.md`.

### Plugins and behavior

- CORS: allow credentials; origin allowed if it is `PUBLIC_WEB_ORIGIN`, exactly matches an entry in
  `ALLOWED_ORIGINS`, or matches a wildcard entry like `https://*.azurestaticapps.net` (dev only).
  Allowed headers: `content-type`, `authorization`, `x-afi-csrf`.
- Helmet with defaults (API returns JSON, so CSP is minimal).
- Rate limit: global 300 req/min per IP; individual routes override later (auth endpoints are stricter).
- Trust proxy: `trustProxy: true` (App Service front ends set `X-Forwarded-For`).
- Error handler returns `{ error: { code, message } }`; zod errors → 400 `validation_error` with details;
  unknown errors → 500 `internal_error` and are logged with the request id.
- Request logging via Fastify's pino logger; redact `authorization`, `cookie`, and any `email` fields at `info` level.

### Initial schema (migration `0000`)

The first migration must start with extensions (write a custom SQL migration with `drizzle-kit generate --custom`
for this part):

```sql
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS citext;
CREATE EXTENSION IF NOT EXISTS pgcrypto;
```

Then Drizzle tables:

```ts
// settings.ts
export const siteSettings = pgTable('site_settings', {
  key: text('key').primaryKey(),               // e.g. 'feature_flags', 'home.hero'
  value: jsonb('value').notNull(),
  isPublic: boolean('is_public').notNull().default(false),
  updatedBy: text('updated_by'),
  createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
  updatedAt: timestamp('updated_at', { withTimezone: true }).notNull().defaultNow(),
});

// audit.ts
export const auditLog = pgTable('audit_log', {
  id: uuid('id').primaryKey().defaultRandom(),
  actorType: text('actor_type').notNull(),     // 'admin' | 'user' | 'system'
  actorId: text('actor_id'),
  actorEmail: text('actor_email'),
  action: text('action').notNull(),            // 'endorsement.update', ...
  entity: text('entity').notNull(),
  entityId: text('entity_id'),
  diff: jsonb('diff'),
  ip: text('ip'),
  createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
}, (t) => [index('audit_log_entity_idx').on(t.entity, t.entityId), index('audit_log_created_idx').on(t.createdAt)]);
```

Seed migration (`0001`, custom SQL) inserts:

```sql
INSERT INTO site_settings (key, value, is_public) VALUES
  ('feature_flags', '{"signup":false,"myDistrict":false,"articles":false,"notifications":false}', true)
ON CONFLICT (key) DO NOTHING;
```

### Routes

- `GET /v1/health` → `200 { status: "ok", db: "ok", version: "<git sha>" }`; `503` with `db: "error"` if `SELECT 1` fails.
  The git SHA comes from env `GIT_SHA` injected at build time (esbuild `define`).
- `GET /v1/config` → `{ featureFlags: {...}, settings: { <public keys>: value } }` from rows where `is_public = true`.
  Cache in memory for 30 seconds.

### `migrate.ts`

Connect with `DATABASE_URL`, `SELECT pg_advisory_lock(727274)`, run drizzle's `migrate()` with the migrations folder,
then unlock and exit non-zero on failure.

```js
const BASE = import.meta.env.VITE_API_BASE_URL ?? '';
export async function api(path, { method = 'GET', body, headers, signal } = {}) {
  const res = await fetch(`${BASE}${path}`, {
    method,
    credentials: 'include',
    headers: { ...(body ? { 'content-type': 'application/json' } : {}), 'x-afi-csrf': '1', ...headers },
    body: body ? JSON.stringify(body) : undefined,
    signal,
  });
  if (!res.ok) {
    const err = await res.json().catch(() => ({}));
    throw Object.assign(new Error(err?.error?.message ?? res.statusText), { status: res.status, code: err?.error?.code });
  }
  return res.status === 204 ? null : res.json();
}
```

- Add `react-router-dom`; in `main.jsx` render a router with `/` → `EndorsedMap`, and a `*` → simple NotFound page.

## Part E — CI/CD workflows

Create:

### `.github/workflows/ci.yml` (pull requests)

- Runs on `pull_request` to `main`.
- Service container `postgis/postgis:16-3.4` for tests; set `TEST_DATABASE_URL`.
- Steps: checkout, setup-node (`node-version-file: .nvmrc`, cache npm), `npm ci`, `npm run lint --if-present`,
  `npm test`, `npm run build`.
- Also run `az bicep build --file infra/main.bicep` (install Bicep via `azure/bicep` setup or the Azure CLI image).

### `.github/workflows/deploy.yml` (main → dev → prod)

Trigger: `push` to `main` and `workflow_dispatch`. Jobs:

1. `build` — `npm ci`, `npm test`, build all three apps with `GIT_SHA=${{ github.sha }}`. For the web build set
   `VITE_API_BASE_URL` per environment, so build the web app **twice** (dev and prod) into
   `apps/web/dist-dev` and `apps/web/dist-prod` (use `vite build --outDir`). Do **not** pass
   `VITE_CONGRESS_API_KEY` (never put it in CI again). Upload artifacts: `web-dev`, `web-prod`, `api` (dist + `package.json` with external deps + migrations),
   `jobs` (dist + host.json + package.json).
2. `deploy-dev` (`environment: dev`, needs build):
   - `azure/login@v2` (OIDC).
   - **Migrate**: add the runner's IP to the Postgres firewall, run `node dist/migrate.js` with `DATABASE_URL`
     fetched from Key Vault (`az keyvault secret show ... --query value -o tsv`, then `::add-mask::`), and remove the
     firewall rule in an `if: always()` step.
   - **API**: `azure/webapps-deploy@v3` with `app-name` = dev API, `package` = api artifact folder.
     Then poll `https://<api-host>/v1/health` until `200` (max 3 minutes).
   - **Jobs**: deploy with `Azure/functions-action@v1` (a version that supports Flex Consumption) using the jobs artifact
     with `remote-build: false`; if it fails on Flex, fall back to `az functionapp deployment source config-zip --src jobs.zip`.
   - **Web**: get the SWA token (`az staticwebapp secrets list -n stapp-afi-dev --query properties.apiKey -o tsv`,
     mask it) and run `Azure/static-web-apps-deploy@v1` with `action: upload`, `app_location: apps/web/dist-dev`,
     `skip_app_build: true`, `skip_api_build: true`.
3. `deploy-prod` (`environment: prod`, needs deploy-dev, requires reviewer approval):
   - Same migrate step against prod.
   - API, jobs, and web exactly as in dev, using prod names and `dist-prod`. Deploy straight to the production
     app (no slots); a short outage while the API restarts is acceptable.

### `.github/workflows/preview.yml` (PR previews for the web app)

- On `pull_request` (opened, synchronize, reopened, closed).
- Build `apps/web` with `VITE_API_BASE_URL=https://<dev api host>`.
- Deploy to the **dev** SWA with `Azure/static-web-apps-deploy@v1` (`action: upload`); on `closed`, `action: close`.
- The dev API must allow `https://*.azurestaticapps.net` origins and set session cookies with `SameSite=None; Secure`
  in dev only (previews are cross-site to the API). Prod cookies stay `SameSite=Lax`.

## Part F — Custom domains (prod)

Dev uses default hostnames (`*.azurestaticapps.net`, `*.azurewebsites.net`). Prod:

1. **API domain**
   - **HUMAN**: create DNS records at `<DNS_PROVIDER>`:
     - `CNAME api → <prod api default hostname>`
     - `TXT asuid.api → <custom domain verification id>` (get it with
       `az webapp show -g rg-afi-prod -n <api> --query customDomainVerificationId -o tsv`).
   - Agent: `az webapp config hostname add --webapp-name <api> -g rg-afi-prod --hostname api.<DOMAIN>`, then create and
     bind an App Service managed certificate:
     `az webapp config ssl create -g rg-afi-prod -n <api> --hostname api.<DOMAIN>` and
     `az webapp config ssl bind --certificate-thumbprint <thumb> --ssl-type SNI -g rg-afi-prod -n <api>`.
   - Verify `curl https://api.<DOMAIN>/v1/health`.
2. **Front-end domain**
   - **HUMAN**: replace the records that pointed at the deleted legacy App Service (saved in `values.md` in step 1) with:
     - `www CNAME → <prod SWA default hostname>` (replaces `www CNAME americafirstindex.us`)
     - `@ A → <prod SWA stableInboundIP>` (replaces `@ A 20.118.56.16`). Get the IP with
       `az staticwebapp show -n stapp-afi-prod --query stableInboundIP -o tsv`.
     - Delete the legacy `asuid` TXT record.
   - **Decision (step 2):** GoDaddy has no ALIAS/ANAME or CNAME flattening, so the apex uses an `A` record to the SWA's
     stable inbound IP ([Microsoft guide](https://learn.microsoft.com/en-us/azure/static-web-apps/apex-domain-external)).
     Apex traffic is served from one regional host instead of SWA's global distribution; acceptable for Phase 1.
     Moving DNS to Azure DNS (alias record) is the upgrade path if that matters later.
   - Agent: `az staticwebapp hostname set -n stapp-afi-prod --hostname www.<DOMAIN>` (CNAME validation) and for the apex
     `az staticwebapp hostname set -n stapp-afi-prod --hostname <DOMAIN> --validation-method dns-txt-token`; read the token with
     `az staticwebapp hostname show` and have the human add it as a TXT record at `@`.
   - The apex is canonical. In the SWA portal "Custom domains" blade, mark it as the default domain so requests to
     `www` redirect to it.
